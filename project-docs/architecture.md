# システム構成 / データフロー

## 構成図

```
[スマホのブラウザ]
  docs/index.html + docs/app.js  <-- GitHub Pagesから配信
        |  localStorage (設定・履歴・下書き)
        v
  (手動コピペ) --> claude.ai の通常チャット --> (手動コピペ)
        |
        v
  カード表示・重複警告・文字数表示
        |
  (手動コピー) --> X の投稿画面(Web Intentでプリフィル可) --> 利用者がタップして投稿
```

サーバー・データベース・APIキーは存在しない。

## データフロー

1. 起動時に`localStorage`から`settings`(furutore_settings_v2)・`history`(furutore_history_v2)・
   `drafts`(furutore_drafts_v2)・`qtDrafts`(furutore_qt_drafts_v2)を読み込む。
2. 「指示文を作る」で、設定+直近履歴(最大20件)+頻度ゲート判定結果をテンプレートに
   埋め込んだ文字列を`#promptText`に表示する。
3. 利用者がclaude.aiに貼り付け、返答をコピーして`#pasteArea`に貼り付ける。
4. 「解析してカード表示」で、貼り付けテキストの最初の`[`〜最後の`]`を抜き出して`JSON.parse`し、
   `state.drafts`に格納、`localStorage`にも保存(ブラウザを閉じても下書きが残るように)。
5. 各カードの「使用済みにする」を押すと、そのエントリを`state.history`に追加して保存する。
   履歴に入るのは「使用済みにした」ものだけで、生成されただけの下書きは重複判定の
   参考(同一バッチ内比較)にのみ使う。

## localStorageキー

| キー | 内容 |
|---|---|
| `furutore_settings_v2` | ペルソナ・過去投稿例・note誘導・鉄板テーマ・巡回アカウント・アフィリエイト・検索キーワード・投稿タイプON/OFF・目標文字数・スレッド許可・生成件数 |
| `furutore_history_v2` | 使用済み投稿・引用RTコメントの配列(`id, ts, kind, type, topic, text`) |
| `furutore_drafts_v2` | 直近生成した(未使用含む)投稿下書きの配列 |
| `furutore_qt_drafts_v2` | 直近生成した引用RTコメント下書きの配列 |

## 重複防止の二重構造

1. プロンプトレベル: 直近20件の使用済み履歴本文をそのまま指示文に埋め込み、AIに重複回避を指示する。
2. クライアントレベル: 生成されたテキストと(a)使用済み履歴全件、(b)同一バッチ内の他カード、を
   bigramのJaccard類似度で比較し、0.35以上で警告バッジを表示する(生成をブロックはしない)。

## 頻度ゲート

- 直結型(note誘導): 直近44時間以内に使用済みなら、今回の投稿タイプ候補から除外
- デザイン思考テスト/デザシコ言及: 直近44時間以内に言及した履歴があれば、
  「今回は一切言及しない」という指示をプロンプトに追加
- 企業紹介型: 「生成時にClaude側の検索機能を使う想定にする」がOFFの場合、候補から除外

## タイプ自動割当ロジック

有効な投稿タイプのうち、直近15件(引用RTを除く)での使用回数が少ないものを優先し、
生成件数ぶん先頭から割り当てる(タイプ数より生成件数が多い場合は先頭から巡回)。
同数の場合はランダムシャッフルしてから安定ソートすることで、常に同じ順にならないようにしている。

## 検索キーワードの自動割当ロジック(話題の偏り防止・2026-08-19追加)

実運用で「生成するたびに同じような内容になりやすい」という報告があったため、
タイプ割当と同じ考え方を検索キーワードにも適用した。

- 設定の「検索キーワード」欄を`[カテゴリ名]`見出しで解析し、見出しに「締切」「時期トレンド」を
  含むカテゴリを`timely`(旬な話題)、それ以外を`evergreen`(定番トピック)の2つのプールに分ける。
- 生成のたびに、`timely`から1件、残りは`evergreen`から、直近40件(`KEYWORD_LOOKBACK`)の
  履歴で使用回数が少ない順に、生成件数ぶん割り当てる(同一バッチ内で重複しないようにする)。
- 割り当てたキーワードは「◯件目: ○○型／起点キーワード:「××」」という形で指示文に明記し、
  AIに対して「自分の判断で使い慣れたテーマに差し替えない」ことを明示的に指示する。
- AIの回答JSONに`keyword`フィールドを追加し、実際に起点として使ったキーワードを申告させる。
  「使用済みにする」を押した時点でこの値を履歴に記録し、次回以降の使用回数カウントに使う。
- キーワード一覧が空、または割当対象が尽きた場合は`null`を割り当て、その投稿だけは
  従来通りAIが自由にテーマを選ぶ(一覧全体をAIに提示する補助的な使い方も残している)。
