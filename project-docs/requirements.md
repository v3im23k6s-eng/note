# 要件定義書 — フルトレ Content Lab v2

## 1. ツールの目的

- 解決したい問題: 就活支援Xアカウント「フルトレ就活」(@fluture_74)の投稿文・引用RTコメントを、以前使っていたツール(claude.ai内蔵Artifact)で発生していた「設定リセット」「重複生成」を再発させずに、日々の作業として続けられるようにする。
- 想定利用者: アカウント運用者本人(1名)。非技術者。
- 利用場面: 1日1回、スマートフォンから作業する。
- 最終的に実現したい状態: ホーム画面から開いて、生成→コピー→Xへ手動投稿、までを毎日数分で完結できる状態。
- 成功と判断する条件:
  1. スマホのブラウザを閉じて再度開いても設定・履歴が保持されている
  2. 直近の履歴と重複した投稿案に警告が出る
  3. 1回の生成で6〜8件のカードが表示される
  4. 各カードをコピーしてXにそのまま貼り付けられる
  5. `account_profile.py`の実績・数字がすべて実データで裏取りできる
  6. APIキー・パスワード等を一切保存・送信しない

## 2. 対象範囲と対象外

対象:
- 投稿文・引用RTコメントの生成支援ツール(Web版、`docs/index.html` + `docs/app.js`)
- 過去ツイート分析による `analysis/account_profile.py` の作成、およびペルソナ文への反映
- 投稿に添える画像の作成支援(2026-08-19追加): (a)投稿文をブランドカラーのカード画像に変換する機能(ブラウザ内で完結、API不要)、(b)外部の無料AI画像生成ツールに貼り付けるための画像生成プロンプト作成機能。どちらもカード単位のボタンで、どの投稿を画像化するかは利用者が都度選ぶ

対象外(スコープ外として合意済み):
- Xへの自動投稿・X公式API連携
- 常時稼働・サーバー・スケジューラー
- tweets.js以外のXアーカイブデータ(DM・フォロワー一覧・IPログ等)の利用

## 3. 投稿に関する仕様

| 項目 | 内容 |
|---|---|
| 投稿文の作成方法 | 設定+履歴から組み立てた指示文を、利用者が手動でclaude.aiにコピペし、返ってきたJSON回答を再度ツールに貼り付けて解析する |
| 投稿元データ | ペルソナ・過去投稿例・note誘導リンク・鉄板テーマ・検索キーワード・投稿タイプ(すべて利用者が編集可能な設定) |
| 投稿スケジュール | 1日1回、手動起動。自動スケジューリングなし |
| 対象アカウント | @fluture_74(フルトレ就活)1アカウントのみ |
| 画像・動画 | 扱わない(テキストのみ) |
| URLの扱い | note誘導リンクは直結型でのみ使用。他タイプでは使用しない |
| ハッシュタグ | 投稿文中にAIが直接含める想定(卒業年度+就活+就職活動が定番パターン、account_profile.py参照) |
| 文字数超過時の扱い | 目標文字数(40〜400でクランプ、既定130字)を意識しつつ、140字超はスレッド機能ONの場合のみ複数パートに分割可 |
| 重複投稿の防止 | (a)生成プロンプトに直近履歴を埋め込みAIに回避させる、(b)クライアント側でbigram Jaccard類似度0.35以上を警告表示(ブロックはしない) |
| 投稿前確認 | 生成された文章は必ず利用者が目で見て選び、コピーしてから手動でXに貼り付ける(自動投稿なし) |
| 予約・即時・定期投稿の区分 | 区分なし(その場でコピーしてすぐ投稿する運用のみ) |
| 投稿成功/失敗判定 | ツール側では判定しない(Xへの実際の投稿はツールの外で行われるため) |
| 投稿履歴・ログ | localStorageに`type/topic/text/日時`を保存。画面内の「トレーニング履歴」で閲覧・個別削除・全削除が可能 |
| 再試行方法 | 生成に失敗した場合は同じ指示文で再度Claudeに送るか、STEP1をやり直す |
| 通知方法 | なし(利用者が自発的に開く運用) |
| 停止方法 | ブラウザでページを閉じるだけ。バックグラウンド処理は存在しない |

## 4. 非機能要件

- 実行環境: モバイルブラウザ(iOS Safari / Android Chrome等)。GitHub Pagesで配信する静的サイト
- OS: 特定しない(Webブラウザが動けば可)
- プログラミング言語: HTML / CSS / Vanilla JavaScript(ビルド不要)
- 常時実行か手動実行か: 手動実行のみ
- 可用性: GitHub Pagesの可用性に依存(SLAなし、個人利用として許容)
- 保守性: 単一HTML+単一JSファイルで完結。フレームワーク・ビルド工程なし
- 拡張性: 将来的にX公式APIでの投稿を追加する場合も、生成ロジックと分離しているため追加しやすい設計
- セキュリティ: APIキー・パスワード等の秘密情報を一切扱わない・保存しない
- ログ: 外部送信ログなし。ローカル履歴のみ
- バックアップ: 手動エクスポート/インポート機能(テキストのコピー&ペースト)
- エラー処理: JSON解析失敗時にエラーメッセージ表示、入力内容は保持
- 運用担当者が行う作業: 1日1回のツール操作、週1回程度の設定見直し(任意)

## 5. 制約事項

- Xの公式APIは使用しない(スコープ外のため利用条件・認証方式の検討自体が不要)
- 認証方式: なし
- API利用上限: なし(Claudeの利用上限は、利用者本人がclaude.aiの通常チャットとして使う分にのみ依存。Proプランを利用中)
- 投稿頻度: 1日1回の生成、6〜8件/回
- 実行環境の制約: GitHub Pagesの公開URLはリンクを知っていれば誰でも閲覧可能(利用者合意済み)。同一ブラウザアプリを使い続ける必要がある(localStorageがブラウザ単位で保存されるため)
- 予算: 追加費用ゼロ(GitHub Pages無料枠、Claude Proは既存契約を利用)
- 使用禁止の手段: X利用規約に反する自動投稿・ログインセッションを利用した擬似操作・スクレイピングは行わない

## 6. 過去の失敗に関する情報

- 過去に作成した仕組み: claude.aiの会話内で動作する類似ツール(Artifact形式)、Claude無料版で運用
- 発生した問題: (a)似たようなツイートが繰り返し生成される問題が最後まで解決しなかった、(b)目標文字数などの設定がツールを開き直すたびにリセットされた
- エラーメッセージ: 利用者からの報告なし(スクリーンショットなし)
- 原因として記載されている事項: なし(利用者からの直接情報なし)
- 原因が未確定の事項: 上記(a)(b)の根本原因は未確定。ただし技術資料(PDF11章)に、Claude内蔵ストレージAPIが`Storage set failed`という原因不明のエラーで断続的に失敗する既知の不具合が記載されており、これが設定リセット・履歴消失(→重複生成)の原因である可能性が高いという仮説を立てている(未検証の推測であることを明記)
- 再発防止策: Claude内蔵ストレージへの依存をやめ、ブラウザ標準のlocalStorageに保存方式を変更。保存後に読み直して検証する処理を追加
