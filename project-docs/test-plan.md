## 不具合修正(実運用フィードバック・2026-08-18)

利用者が実機で6件生成し、1件ずつ「使用済みにする」を押したところ、**全件で「既存の投稿と似ている可能性があります」という警告が出た**という報告があった。

- 原因: 「使用済みにする」を押すとその投稿本文が履歴に追加されるが、直後の再描画でその投稿自身の重複チェックが「たった今追加された自分自身のコピー」と比較され、類似度100%と判定されていた(使用済みカードの自己参照バグ)。
- 検証: 実際のいいね数上位ツイート同士(明らかにテーマの異なるペア)でbigram Jaccard類似度を計算したところ0.05〜0.14程度に収まり、意図的な近い言い換えペアでは0.74〜0.79となることを確認。アルゴリズム・閾値(0.35)自体は適切で、自己参照バグが原因と特定した。
- 修正: 使用済み(`used:true`)のカードでは重複チェックを行わないように変更。
- 再テスト: ユーザー報告を再現する統合テスト(6件生成→1件ずつ使用済みにする)を追加し、修正後は誤警告が0件になることを確認。あわせて、本物の近い言い換えを貼り付けた場合は引き続き警告が出ることも確認し、検知能力自体は損なわれていないことを確認した。

## 今後の観点(機能追加時に追加すべきテスト)

- 認証失敗・通信エラー・APIエラー・レート制限: 本ツールはAPI通信を行わないため対象外
  (将来X公式APIでの投稿を追加する場合は、この節を拡張する)
- 文字数や入力形式の不正: `targetLen`の全角数字入力・範囲外入力のクランプ処理
- 同一内容の重複: 上記#8で確認済み
- プロセス再起動後の二重投稿: 本ツールは投稿を代行しないため、二重投稿はXアプリ側の操作に依存する
- ログに秘密情報が残らないこと: 秘密情報自体を扱わないため該当なし
